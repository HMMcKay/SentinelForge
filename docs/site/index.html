01 / Simulate

Create a behavior inside a defined boundary.

Eight allowlisted scenarios cover benign process chains, encoded PowerShell, scoped registry and task activity, localhost interaction, and file-burst behavior against a synthetic corpus. Dry-run, independent lab gates, and cleanup manifests make the boundary explicit.

Inspect the simulation runner ↗

Contract at this boundary

Known scenario + owned sandbox + cleanup manifest. No arbitrary remote scripts or user-selected targets.

No Windows VM? The seeded demo enters at ingestion with deterministic synthetic events. It exercises detection and investigation without claiming that a real endpoint performed the behavior.

03 / Deliberately bounded architecture

Separate trust boundaries.
One modular backend.

The Windows sensor lives where Event Log and DPAPI access are available. The API keeps ingestion, correlation, and alert persistence together. PostgreSQL stays off the host network.

One active API instance is supported. The local stack binds to loopback; remote sensor traffic needs a reviewed TLS and firewall boundary.

05 / What the work demonstrates

Engineering choices

This independent, AI-assisted project makes design choices reviewable across several disciplines. The source, tests, and decision records show how those choices fit together.

01

Windows telemetry and delivery

Event XML normalization, process GUID lineage, a durable bounded spool, delivery retry, and DPAPI-protected sensor identity. Event-source abstractions separate portable tests from real Windows integration.

02

Detection engineering

A validated Sigma-like subset with unsupported features rejected explicitly. Stateful sequences and thresholds use grouping, time windows, deduplication, and retained evidence. Positive and near-miss fixtures support regression.

03

Security and system design

Strict schemas, idempotent ingestion, separate sensor/operator credentials, internal database networking, bounded queries, and allowlisted reversible simulations. A STRIDE threat model records assumptions and residual risk.

06 / Evidence, with limits

A reproducible lab.
Not an EDR claim.

The July 27, 2026 validation record documents backend, frontend, CLI, sensor, scenario-safety, and browser checks. It also identifies the Windows integrations that were not exercised.

Those recorded results are dated evidence, not a guarantee about every future checkout. Repository workflows expose current build and test results.

What this project does not prove

  • No EDR or SIEM equivalence, kernel sensor, anti-tamper, or protected telemetry path.
  • No full ATT&CK or Sigma coverage. The rule and technique catalogs are deliberately small.
  • Synthetic positives do not establish effectiveness against every variation or evasion.
  • Portable sensor tests do not prove real Sysmon collection, Windows service installation, or every DPAPI service identity.
  • The trusted local-lab access model is not internet-facing, multi-tenant production authentication.

07 / Try the local lab

Start with the demo.
No Windows VM needed.

Use Docker with Compose v2 and PowerShell 7. The bootstrap script generates ignored local secrets and starts the stack. Live Windows behaviors remain separately lab-gated.

PowerShell / local checkout 
git clone https://github.com/HMMcKay/SentinelForge.git
cd SentinelForge
./scripts/bootstrap.ps1
docker compose --profile tools run --rm sentinelctl demo seed --seed 1337

  1. Open http://127.0.0.1:8080.
  2. Choose an alert and read its matched evidence.
  3. Open Timeline, select the alert, and replay its chain.
  4. Compare the result with the rule and its near-miss fixtures.
